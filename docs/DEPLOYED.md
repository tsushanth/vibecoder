## Generate endpoint auth gate 2026-11-23 (PR #142, main 38be704): backend v70, REPORT mode
- Fly `vibecoder-api` release v70 from origin/main (backend tree a9ae11ef identical to main), image deployment-01M83JSFGHHKE7KADFVAE57V43. `npm test` 841/841 on the PR branch before merge. POST /api/projects/generate used to trust the userId in the body. New gate `lib/generateAuth.js` behind GENERATE_AUTH_MODE (off | report | enforce; unset or a typo means report): in report mode behavior is unchanged for every request, each request is classified in the background (no_token, token_invalid, token_mismatch, token_match, internal_ok) and counted by platform and app version without ids, tokens or prompts; counters are per machine, in memory, and reset on restart; read them with the worker secret at GET /api/generate-auth/stats (401 without it). Internal callers (the Telegram bot loopback) sign with `x-internal-auth` (HMAC over timestamp and user id with WORKER_SECRET, 5-minute window, constant-time compare, no IP trust). Checked after deploy: health 200, stats 200 with the worker secret (mode report, total 0 one minute after the release), webhook with a wrong secret 401.
- NOT done on purpose: enforce mode. Plan in docs/security-generate-auth.md: watch the counters for at least 7 days, fix any no_token or token_invalid traffic from the web or current Android, make the same signing change in sms-bot before it goes live, then `flyctl secrets set GENERATE_AUTH_MODE=enforce -a vibecoder-api`. Rollback: set the flag back to report or off. Known risks for enforce: an auth-lookup outage counts as token_invalid (builds refused), old anonymous device-id traffic would be refused, the Android x-app-version header only exists from the next app release. The Android change (x-app-version) is merged but not released.
- Rollback: `flyctl releases rollback 69 -a vibecoder-api`.
